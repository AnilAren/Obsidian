
| Source                   |                                                                                                                    Chunking strategy (best) |                                Size / overlap | Metadata to store                     | When to use                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------: | --------------------------------------------: | ------------------------------------- | ---------------------------------------------- |
| **PDF (native text)**    |                                                                  Page-level, paragraph-level, plus overlap; extract table chunks separately |                      500–1,200 tokens; 10–20% | `page_no`, `coords`, `pdf_id`         | Document QA; legal/policy docs                 |
| **Scanned PDF / Images** |                                                                               OCR → treat OCR text like PDF; also caption + image-embedding |                    OCR confidence; same sizes | `ocr_conf`, `image_id`                | Scans / screenshots                            |
| **HTML / Webpages**      |                                                                            Section-based (H1/H2 boundaries), article body split by headings |    400–1,000 tokens; keep headings with chunk | `url`, `css_selector`, `last_mod`     | Articles, docs, FAQs                           |
| **Excel / CSV / Tables** |                               **Hybrid**: Row-level (for lookup) + table summary + grouped row-chunks for scale. also db for better results |   Row chunks = single row; group = 10–50 rows | `sheet`, `row_id`, `col_schema`       | Numeric lookups (SQL) + semantic queries       |
| **Audio / Video**        |                                                                 ASR transcript → speaker-turn chunks or 30–90s semantic chunks + timestamps | 30–90s windows or speaker turns; overlap 2–5s | `start_ts`, `end_ts`, `speaker`       | Meetings, podcasts                             |
| **Images (no text)**     |                                                                        Captioning → text chunk; optional image embeddings for visual search |                 caption length ~1–3 sentences | `image_id`, `caption_model`, `tags`   | Photos, diagrams, UI screenshots               |
| **Emails (EML/MSG)**     |                                                                                          Per-message chunk; separate out thread/quoted text |                message-level; include subject | `from`, `to`, `date`, `thread_id`     | Support tickets, communications                |
| **Code / Repos**         |                                                                 Function/class-level chunks + file-level summary + README as separate chunk |              function-level or 200–500 tokens | `file_path`, `line_start`, `language` | Code search, explainers                        |
| **Databases / SQL**      | **Don’t embed primary table for exact lookups** — use SQL retriever; create summaries or representative row embeddings for semantic queries |  N/A for SQL; if embedding rows use row-level | `pk`, `table_name`, `schema`          | Exact queries via SQL; patterns via embeddings |
