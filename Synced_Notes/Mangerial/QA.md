#### Explain a microservices architecture to a non-technical executive. What business problems does it solve?

Microservices architecture means breaking a large application into many small, independent services.  
Each service handles one business function — like payments, login, reports, or notifications.

These services can be developed, deployed, and scaled separately.  
So if one service needs more performance or changes, we can update it without affecting the whole system.

Atomicity means a transaction should be treated as a single unit — it either completes 100% or rolls back completely.  
So if a critical transaction fails halfway, I would let the database rollback automatically or manually trigger a rollback so no partial changes remain.

I would wrap the operation in a `BEGIN TRANSACTION` block with proper error handling.  
If any step fails, the system should catch the error and issue a `ROLLBACK`, ensuring the entire transaction is undone.  
Only if all steps succeed should we commit the transaction using `COMMIT`.
